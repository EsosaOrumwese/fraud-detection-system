## Evidence Block 2 - Advanced Analytics, Complex Datasets, SQL/Python, Modelling, and Forecasting

The strongest evidence is the Fraud Risk Intelligence Platform. The situation was an operational analytical environment with multiple data surfaces: events, decisions, entity histories, labels, case movement, controls, and reporting evidence. The problem was not simply to query one table. The work required linking datasets with different grains, checking keys, validating relationships, and producing analytical outputs that could support performance review, prioritisation, and planning.

The action was to use SQL and Python to build linked analytical datasets and repeatable transformation workflows. I defined the grain of each dataset, checked joins and keys, traced source relationships, and documented assumptions so the outputs could be trusted. This gives a strong evidence base for extracting, linking, and analysing large complex datasets using advanced technical information skills.

For modelling, the strongest evidence is forecasting and planning work. I built demand-planning evidence with a 7.31% test MAPE. The value of that result was not the metric alone; it showed how much forecast error should be expected when using the output for planning. This is relevant to demand and capacity work because forecasting only becomes useful if the uncertainty is visible and the user knows how cautiously to use it.

The platform also produced prioritisation evidence showing 2.29x baseline yield in the highest-risk band. The practical interpretation was that work could be concentrated in a way that improved review efficiency, reduced low-value effort, and supported better use of limited capacity. The performance-intelligence pattern is clear: use analysis to identify where pressure or value is concentrated and how planning or review effort should be directed.

The COVID-19 policy/activity analysis adds structured-data scale and public-interest context. I combined 1,004 daily CSV files in Python into 2,396,549 observations and 12 variables across 220 countries and 1,004 days, integrating Facebook Business Activity Trends data with Oxford COVID-19 Government Response Tracker policy data. That work required checking coverage, missingness, duplicates, country/date validity, metric suitability, and source limitations before interpreting trends.

## Evidence Block 3 - Performance Intelligence, BI, KPIs, Dashboards, Productivity, and Efficiency

The relevant scenario from the platform was the need to understand operational pressure and review performance rather than simply produce model outputs. The useful questions were: where is demand concentrated, where are review volumes building, which routes create downstream pressure, which outputs are stable enough to monitor, and which signals require escalation or further investigation.

The action was to design KPI and monitoring outputs around trends, exceptions, data integrity, model yield, demand pressure, and case flow. These were structured as visual and tabular reporting views so that a user could see what changed, where the pressure sat, and what required attention. This is the core BI evidence: dashboards, KPIs, operational reporting, and meaningful intelligence rather than raw extracts.

The productivity and efficiency evidence comes from the prioritisation work. A 2.29x baseline yield in the highest-risk band showed that the highest-priority group contained a much stronger concentration of relevant cases than the general baseline. In operational terms, that supports review efficiency because it helps separate higher-value attention from lower-yield workload. In a healthcare BI context, the same analytical pattern is useful for demand/capacity and productivity work: identify where workload, risk, or pressure is concentrated so decisions are not made from averages alone.

The COVID-19 analysis also supports performance intelligence because it moved beyond raw time series. It linked activity changes to policy context and documented external evidence, which is the same interpretative discipline needed for deep dives: not just "activity changed", but "activity changed at this point, under this context, with these limitations, and this is what can be responsibly inferred."

## Evidence Block 4 - Data Quality, Validation, Governance Awareness, Automation, and Documentation

The platform required strong validation because the outputs depended on linked data and repeated transformations. A failure in one source, join, control, or label definition could distort the analysis. The situation therefore required a quality-first approach before any output could be trusted for decision support.

The action was to apply checks across schema consistency, completeness, duplicates, source traceability, reconciliation, train/test separation, leakage prevention, validation outputs, and documented assumptions. When anomalies appeared, I separated source-data issues from transformation, modelling, linkage, control, and interpretation issues. This matters because the fix depends on the error class. If the source is wrong, changing the dashboard is not enough; if the transformation is wrong, the source should not be blamed.

I also automated recurring checks and reporting preparation so outputs could be repeated rather than rebuilt manually. Definitions, reporting logic, validation outcomes, assumptions, limitations, and handover notes were documented to make the work reviewable and repeatable. This is relevant to the Trust requirement for procedures, standard operating processes, service continuity, automation, and improvement of extraction/manipulation/analysis methods.

For governance, the evidence supports Data Protection awareness, confidentiality-aware handling, controlled access thinking, and GDPR-aware practice. The final wording can also show understanding of information governance, confidentiality, records discipline, FOI consistency, and Caldicott principles in healthcare reporting, while avoiding any claim of direct FOI response ownership or direct Caldicott operational practice.

## Evidence Block 5 - Communication, Interpretative Narrative, Decision Support, and Challenge

The strongest communication evidence is translating technical results into decision terms. In the platform, a metric was not useful unless it explained an operational implication. For example, 7.31% test MAPE was not just a modelling score; it showed the expected planning error and therefore how cautiously the forecast should be used. The 2.29x baseline yield was not just a model result; it showed where review effort was likely to be more productive.

The action was to write findings around four questions: what changed, why it mattered, how reliable the evidence was, and what action or further review was justified. This is the right pattern for an NHS performance intelligence role because managers need interpretation, not raw extracts. The same applies to pressure-point intelligence: a dashboard should not just show red or green; it should explain whether the movement is real, whether it reflects data quality, whether it needs escalation, and what can be done next.

The COVID-19 analysis supports this communication evidence because it required explaining activity changes in policy context without overstating causality. I separated what the data showed from what external evidence supported and what remained uncertain. That is a useful discipline for contentious or delicate analytical conversations because it allows challenge without exaggeration.

The final statement should frame the communication evidence around designing and writing analytical outputs for non-technical decision use, adapting format and level of detail for different audiences, and explaining pressure, uncertainty, limitations, and next steps clearly.
