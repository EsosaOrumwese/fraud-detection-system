# Thames Water — Data Analyst: 3 Screens

## 1. Business / problem screen

Thames Water is not hiring for a pure ML role, a payments/fraud role, or a finance reporting role. This is an **operational analytics** role inside **Water Networks Operations**, where the analyst turns complex data into usable insight for operational decisions and change. The job ad frames the role around operational analytics, water networks insight, reporting, dashboards, stakeholder decision support, large datasets, SQL, Power BI, Python/R and operational data quality.

| Thames business problem | What the CV needs to show |
| --- | --- |
| Water networks operational insight | You can analyse operational data and turn it into practical insight for service/operations teams. |
| Large varied datasets | You can work with internal and external datasets, including operational, environmental and survey-type data. |
| Operational decision support | You can convert analysis into reports, dashboards or recommendations that help colleagues make decisions. |
| Process and ways-of-working improvement | You can liaise with the business and use analysis to improve reporting, processes or operational visibility. |
| Data quality and reliable reporting | You can identify, clean, validate or improve data so reports are trusted. |
| Secure / GDPR-aware data use | You can handle data responsibly and communicate limitations clearly. |
| High-impact infrastructure context | You understand that operational analytics here affects essential services, not just internal KPIs. |

The strongest business-positioning phrase is probably:

```text
operational analytics and reporting for water networks decision support
```

or:

```text
SQL-led operational insight, Power BI reporting and data quality for infrastructure operations
```

Not:

```text
fraud and chargeback analytics
```

Not:

```text
customer behaviour ML platform
```

Not:

```text
payments-focused data analyst
```

This CV will need to feel like an **operational data analyst** CV: large datasets, SQL, transformations, Power BI/Tableau dashboards, data quality, stakeholder insight, and operational decision support.

## 2. Technical / capability screen

The technical screen is very concrete. Thames wants someone who can work with large datasets, databases or reporting; use query languages such as **TSQL or ANSI SQL**; use dashboarding tools such as **Power BI or Tableau**; and ideally bring scripting capability in **Python or R**. The ad also mentions familiarity with R, Business Objects, Microsoft Azure services and Microsoft Office as helpful.

| Technical requirement | Concrete evidence to look for later |
| --- | --- |
| SQL / database interrogation | SQL operational data queries, SQL reconciliation queries, SQL transformation scripts, database interrogation work. |
| Data transformation | Cleaning, joining, reshaping or standardising operational datasets before reporting. |
| Large datasets | 2.35B-row data surface if relevant, operational datasets, field records, survey data, environmental-style trend data. |
| Power BI / Tableau dashboards | Power BI operational metrics dashboard, reporting pack, KPI dashboard, service/operations visibility report. |
| Python / R scripting | Python data cleaning, Pandas analysis, metric variance analysis, automated checks, modelling if relevant but not over-centred. |
| Data quality | Validation checks, reconciliation workbook, missing/duplicate/conflicting record checks, dashboard QA. |
| Microsoft Office / Excel | Excel reconciliation, pivot tables, lookups, structured reporting, operational summaries. |
| Secure data use / GDPR | Data handling, controlled reporting, communicating limitations, responsible use of sensitive/customer/operational data. |

For this job, **SQL transformation, Power BI reporting, data quality, and operational dashboards are central evidence**. Python is useful, but it should support the story rather than dominate it.

So later, we should be looking for artefacts like:

```text
SQL operational data transformation query
Power BI operational metrics dashboard
Excel reconciliation workbook
data-quality validation checklist
operational reporting pack
stakeholder insight report
metric movement analysis
survey / environmental / operational trend analysis
```

Not vague phrases like:

```text
data analysis
stakeholder reporting
business intelligence
machine learning
```

Those are too broad unless tied to concrete artefacts.

## 3. Working-style / stakeholder screen

This role is strongly business-facing. Thames wants someone who can act as a point of contact, collaborate with colleagues, engage stakeholders, inform operational decisions, bridge business and data, and explain complex information clearly through reports, dashboards and presentations.

| Working-style requirement | CV evidence we should look for later |
| --- | --- |
| Stakeholder engagement | Reports or dashboards produced for operations managers, supervisors, business teams or non-technical users. |
| Clear communication | Decision-ready summaries, visual reports, dashboard commentary, presentations or insight notes. |
| Business liaison | Evidence of working with operational teams to understand reporting needs or improve ways of working. |
| Point-of-contact behaviour | Owning a recurring report, dashboard, data process or operational insight output. |
| Analytical problem solving | Investigating metric movements, reporting gaps, operational delays, data inconsistencies or trend changes. |
| Data limitations communication | Explaining missing data, conflicting records, data-quality risks or confidence limits. |
| Curiosity and learning | Picking up tools, working across datasets, improving reporting processes, using Python/R/SQL to extend analysis. |

The working-style story should become:

```text
I can work with operational stakeholders, interrogate and transform large datasets, build reliable Power BI/SQL reporting, improve data quality, and explain insights clearly enough to support water networks operational decisions.
```
