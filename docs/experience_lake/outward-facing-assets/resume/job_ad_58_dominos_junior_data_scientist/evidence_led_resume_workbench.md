# Domino's Data Scientist - 3 Screens

This is the job-ad interpretation stage only: business/problem screen, technical/capability screen, and working-style/stakeholder screen. No proof buckets, evidence ledger, scoring, or bullets yet.

Use **Data Scientist** for positioning. Do not use "Junior" in the CV title unless we later decide it helps ATS somewhere else. The evidence should still match an early-career, practical, business-facing role.

## 1. Business / Problem Screen

Domino's is not hiring for a heavy ML platform specialist or a fraud/risk modeller. They want someone who can help the business make **smarter, data-led decisions** by cleaning and analysing data, building foundational models, supporting experimentation and reporting, and turning findings into practical outputs that affect operations, customer service and commercial growth.

The business problem is:

```text
Can this person use SQL, Python, modelling and reporting to help Domino's operate better, serve customers better and grow commercially?
```

The CV eventually needs to prove:

```text
cleaned datasets
SQL/Python analysis
basic/foundational modelling
Power BI or visual reporting
experimentation or pre/post comparison
practical recommendations
customer / digital / operational / commercial relevance
clear explanation of findings
```

Domino's is highly digital: the ad says 90% of system sales come through digital channels, 75% of digital orders come through the app, and there are 9.5 million active app customers. Customer/order/app/digital behaviour evidence could be valuable, but only if grounded truthfully.

Strong business direction:

```text
data science for customer, digital, operational and commercial decisions
```

Not:

```text
fraud-risk decisioning
MLOps platform
analytics engineering
data governance
payments/chargebacks
```

## 2. Technical / Capability Screen

Domino's asks for SQL, Python, exposure to Power BI, a quantitative degree, data science fundamentals, basic modelling techniques, confidence with data, and clear explanation of findings.

The technical screen is practical and foundation-focused:

| Requirement | Concrete evidence to look for later |
| --- | --- |
| SQL | SQL analysis tables, KPI queries, customer/order/behaviour tables, period comparisons |
| Python | modelling notebooks, Pandas/NumPy analysis, model evaluation, data cleaning scripts |
| Basic modelling | classification, regression, segmentation, scoring, baseline model, model accuracy |
| Data cleaning | missing values, duplicate checks, inconsistent records, validation checks |
| Power BI / visualisation | KPI dashboards, trend charts, operational dashboards, visual reports |
| Experimentation support | A/B test support, pre/post analysis, threshold comparison, before/after report |
| Reporting | recurring report, dashboard, performance summary, metric table |
| Clear explanation | recommendation note, visual trend report, plain-English summary |

The CV should not sound overengineered. It should show core work done well:

```text
clean data -> analyse it -> build a simple/modelled output -> visualise it -> explain what to do next
```

## 3. Working-Style / Stakeholder Screen

Domino's wants someone early in their data career who can work in a small team, tackle well-defined problems, work independently on technical tasks, stay curious, learn quickly, collaborate across the business, and translate technical work into business value.

The working-style evidence should prove:

| Working-style signal | Concrete evidence to look for later |
| --- | --- |
| Independent technical work | built a model, query, dashboard, workbook, report or validation check |
| Curiosity / learning | tested models, compared baselines, investigated metric movement |
| Collaboration | outputs used by managers, business users, operations, analysts, stakeholders |
| Clear explanation | visual report, recommendation summary, dashboard notes |
| Business value | customer response, operational efficiency, review time, reporting accuracy, commercial opportunity |
| Experimentation mindset | compared options, tested thresholds, measured before/after change |

The working-style story should be:

```text
I can take a defined business/data problem, clean the data, build the analysis or model, and explain the result clearly enough for a business team to use.
```
