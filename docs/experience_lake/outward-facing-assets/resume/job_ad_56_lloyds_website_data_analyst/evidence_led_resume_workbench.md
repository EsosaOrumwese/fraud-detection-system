# Lloyds Website Data Analyst - 3 Screens

This is the job-ad interpretation stage only: business/problem screen, technical/capability screen, and working-style/stakeholder screen. No proof buckets, evidence ledger, scoring, or bullets yet.

This role is about **public website / digital performance analytics**, not generic data analysis, customer segmentation, demand reporting, supplier analytics, or ML.

## 1. Business / Problem Screen

Lloyds is hiring into the **Public Websites team**. Their public websites help customers discover products, complete tasks, and engage with Lloyds/Halifax brands. The analyst supports reporting, insight, performance analysis, tracking, and optimisation across public-facing websites.

The business problem is:

```text
How are customers using our public websites, where are journeys/content/campaigns underperforming, and what should digital/content/marketing/product teams improve?
```

| Lloyds business problem | What the CV must eventually prove |
| --- | --- |
| Website performance reporting | You can build and maintain regular reports/dashboards for digital performance. |
| Customer journey analysis | You can analyse how users move through digital journeys, where they engage, drop off, or complete tasks. |
| Traffic and engagement trends | You can monitor visits, activity, engagement, conversion/task completion or content interaction trends. |
| Content performance | You can show which content/pages/components are working or underperforming. |
| Campaign performance | You can analyse campaign traffic, landing-page performance, audience response or content outcomes. |
| Optimisation opportunities | You can turn trend/journey findings into concrete improvement recommendations. |
| Tracking accuracy | You can validate tracking/reporting outputs so teams trust the data. |

The CV should eventually feel like:

```text
website/customer journey data -> Power BI / analytics dashboard -> trend or content finding -> tracking QA -> optimisation note for digital/content/marketing/product teams
```

Not:

```text
generic dashboarding
customer segmentation
supplier analytics
water demand
fraud/payments
deep learning model evaluation
```

The likely strongest positioning phrase later is:

```text
website performance reporting, customer journey analysis and tracking validation
```

## 2. Technical / Capability Screen

The job is tool-specific. Lloyds wants Adobe Analytics or Google Analytics, Power BI, Excel, website/digital reporting, customer behaviour, digital journeys, website performance metrics, tracking validation, report automation, and clear presentation.

| Technical requirement | Concrete evidence to look for later |
| --- | --- |
| Adobe Analytics / Google Analytics | Direct evidence if available; otherwise do not fake it. |
| Power BI | Website/customer journey dashboard, performance dashboard, content/campaign dashboard, recurring KPI report. |
| Excel | Pivot/reporting workbook, tracking QA log, data validation workbook, campaign/content performance summary. |
| Website metrics | Traffic, engagement, journey steps, content views, clicks, task completion, conversion/drop-off if available. |
| Customer behaviour data | Customer activity table, journey-like lifecycle/activity data, response-history or event data. |
| Tracking validation / QA | Tracking validation checklist, data-quality checks, missing events, duplicate records, mismatched totals, stale refreshes. |
| Report automation | Automated recurring report, VBA/Power Query/Python/SQL refresh process, dashboard source table. |
| Dataset confidence | Large event/activity dataset, dashboard source tables, validated reporting outputs. |

This is where we must be careful. If there is no Adobe/Google Analytics experience, do not invent it. The CV can still compete through:

```text
Power BI dashboarding
event/activity data
customer journey analysis
tracking/data-quality validation
report automation
digital/customer behaviour reporting
```

However, a shortlist-level CV needs **web/digital-performance-adjacent artefacts**, not just "operational metrics."

Concrete artefacts to search for later:

```text
Power BI customer journey dashboard
traffic / engagement trend table
content performance report
campaign performance summary
tracking validation checklist

dashboard refresh process
stakeholder optimisation note
```

## 3. Working-Style / Stakeholder Screen

This role is cross-functional. The analyst works with the Lead Data Analyst and wider **digital, content, marketing, product and technology teams**. They answer business questions, present findings clearly to technical and non-technical audiences, automate recurring reports, and support optimisation activity.

| Working-style requirement | CV evidence to look for later |
| --- | --- |
| Cross-functional stakeholder support | Outputs for digital, content, marketing, product, technology, or equivalent stakeholder groups. |
| Clear communication | Dashboard commentary, performance summary, stakeholder note, optimisation recommendation. |
| Attention to detail | Tracking QA, data validation, mismatch checks, duplicate/missing event checks. |
| Structured problem solving | Journey drop-off analysis, content underperformance review, campaign variance analysis, metric movement report. |
| Reporting ownership | Built/maintained regular dashboard/report across reporting periods. |
| Automation/process improvement | Reduced manual reporting, automated refreshes/checks, improved dashboard reliability. |
| Technical + non-technical audience | Clear dashboard/report for analysts and business stakeholders. |

The working-style story should eventually become:

```text
I can maintain website/digital performance reporting, validate tracking/data quality, explain journey/content/campaign movements, and give digital/content/marketing/product teams concrete optimisation notes.
```
