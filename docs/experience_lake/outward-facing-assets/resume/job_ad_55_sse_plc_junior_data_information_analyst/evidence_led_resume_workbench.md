# SSE Junior Data and Information Analyst - Evidence-Led Resume Workbench

# SSE Junior Data and Information Analyst - 3 Screens

This is the job-ad interpretation stage only: business/problem screen, technical/information-management screen, and working-style/stakeholder screen. No proof buckets, evidence ledger, scoring, or bullets yet.

## 1. Business / Problem Screen

This role is about helping **SSEN Distribution get more value from data by making it easier, safer and more responsible to share and use**. That is the centre of gravity. It is not a modelling role, dashboard role, or commercial analytics role. It sits around **open data, trusted data, responsible data sharing, governance, privacy, security, metadata, data quality, and stakeholder confidence**.

The CV eventually needs to prove evidence around:

| SSE business problem | What the CV needs to show later |
| --- | --- |
| Responsible data sharing | You can check data before it is shared, published, sent, or used by others. |
| Trusted data | You can improve records, reports, definitions, or checks so people trust the data. |
| Data governance | You understand controls, standards, documentation, ownership, and consistent ways of working. |
| Data quality and clarity | You can find missing, duplicated, conflicting, stale, or unclear records. |
| Data users and feedback | You can understand how people use data and turn repeated questions/issues into improvements. |
| Regulation and responsible use | You are careful with privacy, security, lawful use, data limitations, and ethical handling. |
| Real-world impact | You can work with operational or infrastructure-adjacent data where errors affect decisions, safety, service, or trust. |

Strong direction:

```text
data quality, metadata, responsible data sharing and plain-English data support
```

Not:

```text
machine learning platform
product analytics
commercial KPI dashboards
fraud/payments analytics
```

## 2. Technical / Information-Management Screen

This job does not demand a stack like SQL/Python/Power BI as the centre. Tools may help, but the job is really about **information control and data trust**: data requests, open data publication, data standards, metadata, data quality, documentation, governance, and controls for privacy/security/trust. SSE also mentions knowledge of data protection, regulation or compliance.

Concrete evidence to look for later:

| Requirement | Concrete artefacts to mine |
| --- | --- |
| Data request review | request log, access checklist, data-sharing review note, approval tracker |
| Responsible publication | publication checklist, privacy/security control note, data limitation statement |
| Metadata and standards | KPI dictionary, field definition sheet, source table notes, data catalogue entry |
| Data quality | Excel reconciliation workbook, SQL validation query, missing/duplicate/conflicting record checks |
| Documentation | data definition document, report guide, README, lineage note, dashboard notes |
| Compliance awareness | privacy checklist, data handling note, GDPR/data protection training, lawful-use note |
| Trusted reporting | validation checklist, report QA table, refresh/reconciliation log |
| Practical improvements | issue log, feedback tracker, revised template, updated definitions, data-user guide |

Concrete nouns matter here:

```text
Excel reconciliation workbook
field-report QA checklist
KPI definition sheet
data limitation note
metadata dictionary
source-to-report validation query
data-sharing control checklist
stakeholder feedback tracker
plain-English report guide
```

Avoid:

```text
supported governance
enabled trusted data
improved data literacy
enhanced transparency
```

unless attached to a real artefact.

## 3. Working-Style / Stakeholder Screen

SSE wants someone who can work across teams, build relationships, communicate clearly with people from different backgrounds, explain complex ideas in plain English, gather feedback, support workshops/events/webinars, and approach problems with curiosity and responsibility.

The CV eventually needs to show:

| Working-style signal | Concrete evidence to mine |
| --- | --- |
| Plain-English communication | visual report, data guide, dashboard notes, manager summary, data limitation note |
| Stakeholder engagement | feedback log, user questions, workshop slides, meeting notes, revised report after feedback |
| Cross-team work | outputs used by operations, safety, managers, analysts, technical/non-technical users |
| Proactive improvement | added checks, fixed definitions, automated exception flags, reduced conflicting records |
| Trust and responsibility | controlled report sharing, documented limitations, reconciled records before review |
| Learning mindset | data protection/compliance awareness, governance training, new-topic learning examples |

The working-style story should become:

```text
I can make messy operational or analytical data clearer, safer to use, better documented and easier for non-technical people to understand.
```

# SSE Junior Data and Information Analyst - Competitive Proof Buckets

These are not bullets yet. They define what the CV must prove for this specific role.

SSE is hiring for a role centred on **responsible data sharing, open/trusted data, data governance, privacy/security controls, metadata, data quality, stakeholder feedback, plain-English communication and data literacy**. The job ad specifically mentions reviewing data requests, publishing data responsibly, protecting privacy/security/trust, improving standards and metadata, supporting governance strategy, ethical data use, and workshops/events/webinars.

## 1. Responsible Data Sharing And Request Review

| What the CV must prove | Concrete artefacts to look for later |
| --- | --- |
| You can check data before it is shared, published, reported or handed to others. | Data request log, access checklist, data-sharing review note, privacy/security control checklist, report release checklist, approval tracker. |

This is the closest bucket to the heart of the role. A weak CV says "data governance." A strong CV shows the actual control object: **request log, checklist, review note, release check**.

## 2. Data Quality And Record Accuracy

| What the CV must prove | Concrete artefacts to look for later |
| --- | --- |
| You can find and reduce missing, duplicate, conflicting, stale or unclear records before people rely on them. | Excel reconciliation workbook, SQL validation query, exception tracker, missing-record report, duplicate check, field-report QA table, dashboard validation checklist. |

This will probably be one of the strongest buckets because the South Western evidence has field reports, HSE logs, equipment checks, daily completions records, Excel checks and a 32% reduction in incomplete/conflicting records.

## 3. Metadata, Definitions And Documentation

| What the CV must prove | Concrete artefacts to look for later |
| --- | --- |
| You can make data understandable by documenting definitions, source fields, formulas, filters, assumptions and limitations. | KPI definition sheet, metadata dictionary, source-table notes, data limitation note, dashboard guide, report README, lineage note, data catalogue entry. |

This bucket matters because SSE explicitly mentions **standards, metadata and best practice** so people can trust and understand the data they use.

This is where the evidence must stay concrete. Do not say:

```text
supported metadata standards
```

Say:

```text
documented 13 KPI definitions with formulas, source tables, filters and data limitations
```

## 4. Data Governance, Controls And Ethical Use

| What the CV must prove | Concrete artefacts to look for later |
| --- | --- |
| You understand that data needs controls, consistent ways of working, responsible handling and ethical use. | Governance checklist, data-quality standard, report QA process, controlled sharing process, privacy note, security checklist, data limitation statement, audit trail. |

This bucket separates the CV from someone who only builds dashboards. SSE wants someone who thinks about **trust, transparency, lawful use and responsible data handling**, not just analysis.

## 5. Data Protection, Regulation And Compliance Awareness

| What the CV must prove | Concrete artefacts to look for later |
| --- | --- |
| You understand that data must be used responsibly and lawfully, especially when privacy, security or external sharing are involved. | Data protection training, GDPR/privacy awareness note, data handling checklist, restricted-field note, access-control check, anonymisation/masking note, sensitive-data limitation. |

This is a high-risk bucket: do **not** invent compliance experience. If the evidence is limited, show adjacent evidence through careful data handling, controlled report sharing, data limitations and quality checks.

## 6. Data-User Feedback And Practical Improvements

| What the CV must prove | Concrete artefacts to look for later |
| --- | --- |
| You can understand how people use data, capture recurring issues/questions, and turn those into better reports, definitions, checks or templates. | Feedback tracker, issue log, recurring-question list, revised report template, updated KPI definition, dashboard change log, user-request summary. |

This is a competitive bucket because the ad does not just say "communicate"; it says gather feedback from data users and turn that into practical improvements.

Average candidates will say:

```text
worked with stakeholders
```

The CV needs artefacts like:

```text
tracked recurring report questions and updated KPI definitions / report notes / validation checks
```

## 7. Plain-English Communication And Engagement

| What the CV must prove | Concrete artefacts to look for later |
| --- | --- |
| You can explain data clearly to technical and non-technical people in writing, conversation, workshops, reports or summaries. | Plain-English report guide, visual trend report, dashboard notes, manager summary, workshop slides, webinar notes, data limitation explanation, 3-recommendation report. |

SSE explicitly wants communication and engagement, including workshops, events or webinars that explain data clearly and encourage collaboration.

If there is no workshop/webinar evidence, do not fake it. Use **visual trend reports, manager summaries, report notes and plain-English recommendations**.

## 8. Real-World Operational Data And Service Impact

| What the CV must prove | Concrete artefacts to look for later |
| --- | --- |
| You have handled data where errors matter because the data supports operations, safety, service delivery or infrastructure-adjacent decisions. | Field-report reconciliation workbook, HSE log checks, equipment-readiness tracker, completions records, operational KPI dashboard, handover pack, documentation-gap tracker. |

This bucket can make the CV stand out. SSEN Distribution is a real-world infrastructure environment. Oilfield/completions data experience is not the same sector, but it does show **messy operational records, HSE documentation, equipment checks, manager review and traceability**. That is relevant if framed truthfully.

## Priority Order For SSE

I would rank the proof buckets like this:

```text
1. Data quality and record accuracy
2. Metadata, definitions and documentation
3. Responsible data sharing and request review
4. Data governance, controls and ethical use
5. Plain-English communication and engagement
6. Data-user feedback and practical improvements
7. Data protection, regulation and compliance awareness
8. Real-world operational data and service impact
```

Why this order? Because the strongest evidence is likely **data quality, documentation, validation, reconciliation and operational records**, while the job's highest-value signals are **trusted data, responsible sharing, governance and clear communication**.
