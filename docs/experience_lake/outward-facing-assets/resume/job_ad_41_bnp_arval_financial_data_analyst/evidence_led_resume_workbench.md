For **Arval BNP Paribas Financial Data Analyst**, the centre of gravity is:

> **finance data flows, SQL data modelling, large financial datasets, SAS/data governance awareness, finance reporting requests, and communication with non-technical finance stakeholders.**

This is **not** a fraud CV, not a payments/chargeback CV, and not a pure data science CV. The role sits inside the **finance team** and is about improving finance data processing, maintaining data flows, handling finance reporting requests, and upholding data quality/governance.

# 1. Business / problem screen

| Arval business problem | What the CV needs to prove |
| --- | --- |
| Finance team needs better data flows | You can build, maintain, and improve repeatable data flows for reporting or analysis |
| Existing SaaS data processing needs review | You can inspect current data processing, find inefficiencies or gaps, and improve how data is handled |
| Finance has recurring and ad-hoc data requests | You can respond to finance reporting needs with accurate datasets, reports, extracts, or summaries |
| Financial datasets need quality and governance | You can maintain clean, controlled, traceable datasets for reporting use |
| Finance users are non-technical | You can explain data issues, outputs, and changes clearly to finance stakeholders |
| Arval operates in vehicle leasing | Commercial/financial reporting should ideally connect to leasing, customer, contract, fleet, revenue, cost, or operational-finance data if we have evidence |

The strongest business positioning is probably:

```text
Financial Data Analyst | SQL Data Flows | Finance Reporting, Data Quality & Governance
```

or:

```text
Financial Data Analyst | SQL, SAS & Finance Data Modelling | Reporting Data Flows
```

Only include **SAS** in the headline if we can credibly support it.

# 2. Technical / capability screen

The ad's technical screen is clear: **SQL, data modelling, complex datasets, SAS, data governance, large financial datasets, reporting purposes**.

| Technical requirement | Concrete evidence to look for later |
| --- | --- |
| Strong SQL | SQL finance dataset query, SQL reporting table, SQL reconciliation query, SQL view for finance reporting |
| Data modelling | Finance reporting data model, fact/dimension table, dataset schema, reporting-ready table |
| Complex datasets | Large transaction/customer/contract/operational dataset, 2.35B-row data surface if relevant |
| Data flows | SQL data flow, ETL-style reporting workflow, scheduled extract, data pipeline, finance reporting table refresh |
| SaaS data processing review | SaaS export review, data-processing audit, field-mapping table, duplicate/missing-value check, data issue log |
| SAS programming | SAS data step, PROC SQL, SAS reporting dataset, SAS validation output - only if true |
| Data governance | data dictionary, validation checklist, access/definition controls, report definition log, data-quality rules |
| Finance reporting | finance reporting dataset, Excel finance workbook, Power BI finance dashboard, monthly finance pack |
| Data quality | reconciliation workbook, SQL QA checks, duplicate/missing-record checks, dashboard validation checks |

Important: **SQL and finance data flows must dominate**. Python/ML should not dominate this CV unless used to support data quality, automation, or large-dataset processing.

# 3. Working-style / stakeholder screen

The ad wants someone collaborative, finance-facing, process-improvement minded, and comfortable communicating with non-technical finance team members. It also emphasises data quality, governance, and working closely with team members.

| Working-style requirement | CV evidence to look for |
| --- | --- |
| Finance stakeholder communication | Finance report commentary, data request summary, metric definition note, reconciliation explanation |
| Collaboration | Worked with finance, operations, risk, data, or reporting stakeholders to resolve data issues |
| Process improvement | Reduced manual reporting time, improved refresh reliability, standardised data flow, automated checks |
| Data quality ownership | Built validation checks, reconciled source records, resolved duplicate/missing entries |
| Governance discipline | Maintained data definitions, controlled reporting logic, documented data lineage or KPI definitions |
| Handling general requests | Responded to ad-hoc data extracts, reporting queries, variance checks, finance summaries |
| Financial interest/commercial awareness | Linked analysis to revenue, cost, exposure, payment, transaction, operational or contract metrics |

The working-style story should be:

```text
I can build and maintain SQL-led finance reporting datasets, improve data-flow quality, respond to finance data requests, and explain data issues clearly to non-technical finance stakeholders.
```
