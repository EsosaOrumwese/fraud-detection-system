# Monzo — 3 Screens

This is still the **job-ad interpretation stage only**: product/business screen, technical/analytics screen, and working-style/stakeholder screen. No proof buckets, evidence ledger, scoring, or bullets yet.

## 1. Product / business problem screen

Monzo is hiring a **Product Data Scientist**, not a generic modeller. The role is about helping product squads make better decisions about users, engagement, product features, experiments, profitability and strategy. Monzo specifically says the role will help “super charge” user engagement, understand how users interact with products, guide teams to measure what matters, support A/B experiments, and work with finance on lifetime value and user profitability.

So the CV eventually needs to prove evidence around:

| Monzo business/product problem | What the CV needs to show later                                                                               |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| User engagement                | You can analyse user activity, repeat use, drop-off, retention, activation, response, or engagement patterns. |
| Product interaction            | You can show how users interact with a product, feature, journey, dashboard, model, or workflow.              |
| Product strategy               | You can turn analysis into a recommendation that changes what a product/team should do next.                  |
| Experimentation                | You can design, analyse, or simulate A/B-style comparisons with clear metrics and baselines.                  |
| Lifetime value / profitability | You can connect user behaviour to value, cost, risk, revenue, or profitability proxies.                       |
| Growth and retention           | You can identify user groups more likely to convert, return, respond, churn, or become higher-value.          |
| Better decisions faster        | You can build reusable metrics, dashboards, or analysis tables that reduce repeated manual analysis.          |

Strong business-positioning phrase:

```text
product analytics for user engagement, feature impact, experimentation and commercial decision-making
```

But in the CV, we need concrete artefacts like:

```text
SQL user-behaviour table
engagement cohort analysis
activation / retention dashboard
feature-impact report
A/B experiment analysis
holdout or pre/post comparison
LTV / profitability proxy table
Looker product metrics dashboard
event-tracking note for engineers
product recommendation memo
```

## 2. Technical / analytics capability screen

Technically, Monzo wants strong quantitative analysis, SQL, preferably Python, data mining, presentation of data, A/B experiments, Looker/self-serve analytics, and enough product-data understanding to work with engineers on collecting the right data. They also say most day-to-day data decisions are covered by self-serve Looker, which means the higher-value DS work is deeper analysis, experiments and product questions beyond routine dashboarding.

| Technical requirement               | Concrete evidence to look for later                                                                                  |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| SQL analysis                        | SQL cohort table, BigQuery user-behaviour query, SQL feature-impact table, funnel query.                             |
| Python analysis                     | Python notebooks/scripts for modelling, experiments, segmentation, metric analysis, validation.                      |
| Quantitative analysis / data mining | User segmentation, engagement drivers, churn/retention analysis, anomaly/behaviour patterns.                         |
| A/B experimentation                 | Control/treatment table, experiment metric definition, uplift analysis, holdout comparison, pre/post test.           |
| Looker / self-serve analytics       | Looker dashboard, product metrics report, KPI dashboard, metric definitions.                                         |
| Product metrics                     | Activation, engagement, retention, conversion, response rate, churn risk, product usage, feature adoption.           |
| LTV / profitability thinking        | Revenue/cost/risk proxy table, value-segment analysis, user profitability analysis, high-value segment ranking.      |
| Data collection with engineers      | Event-tracking spec, missing-field note, data-quality issue table, instrumentation request, source-table validation. |

The CV should not just say:

```text
quantitative analysis
data-driven product decisions
commercial insight
```

It needs named objects:

```text
BigQuery engagement cohort table
Python retention model
Looker product metrics dashboard
A/B test readout
feature-impact analysis table
LTV proxy table
event-tracking gap list
SQL metric definition table
```

## 3. Working-style / stakeholder screen

Monzo’s Data Scientists work in cross-functional squads with engineers, designers, marketers and product managers, while also belonging to a central data discipline. The ad also stresses impact, commercial mindset, hands-on analysis plus strategic thinking, self-starter behaviour, team reliability and collaboration with finance and engineers.

| Working-style requirement   | Concrete evidence to look for later                                                                              |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Product squad collaboration | Analysis used by product, marketing, engineering, finance, or risk stakeholders.                                 |
| Engineer collaboration      | Event/data collection notes, data-quality checks, missing-field requests, source-table validation.               |
| Finance collaboration       | LTV, user profitability, cost/risk/value proxy analysis.                                                         |
| Commercial mindset          | Analysis tied to user value, profitability, conversion, retention, acquisition, risk, or cost.                   |
| Self-starter behaviour      | Proactively built a dashboard, query, metric table, root-cause report, validation check, or recommendation memo. |
| Strategic + hands-on        | Can write SQL/Python but also explain what the result means for product strategy.                                |
| Clear presentation          | Experiment readout, product recommendation memo, Looker dashboard commentary, metric definition document.        |

The working-style story should become:

```text
I can sit inside a product squad, use SQL/Python to analyse user behaviour, define the right metrics, test whether a product action worked, explain the commercial meaning, and work with engineers or finance when the data or profitability question needs it.
```

This CV should move toward:

Product Data Scientist | User Engagement, Experimentation & Product Analytics | SQL, Python & Looker

or:

For Monzo, the winning story is **product behaviour analysis + experiment-style measurement + commercial interpretation + squad-ready recommendations**.

# Monzo — Proof Buckets

Proof buckets are **not bullets yet**. They answer:

> “What must this CV prove for this specific Monzo role?”

Monzo is hiring a **Product Data Scientist** who can work in a product squad, analyse user behaviour, help teams measure what matters, support A/B experiments, connect features to user profitability / lifetime value, use SQL/Python, and work with engineers so the right data is collected.

## 1. User engagement and product-behaviour analysis

| What the CV must prove                                                                    | Concrete artefacts to look for later                                                                                                                         |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| You can analyse how users interact with a product, feature, journey, segment or workflow. | SQL user-behaviour table, engagement cohort table, retention table, product-usage dashboard, feature-adoption report, response-rate table, churn-risk table. |

This is the central Monzo bucket. The CV should not lead with generic ML. It should show **user behaviour -> product question -> metric -> recommendation**.

## 2. A/B experiment or controlled comparison evidence

| What the CV must prove                                                                               | Concrete artefacts to look for later                                                                                                                |
| ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| You can define success metrics, compare groups, measure uplift, and decide whether an action worked. | A/B experiment readout, control/treatment table, holdout comparison, pre/post analysis, threshold test, uplift table, experiment metric definition. |
