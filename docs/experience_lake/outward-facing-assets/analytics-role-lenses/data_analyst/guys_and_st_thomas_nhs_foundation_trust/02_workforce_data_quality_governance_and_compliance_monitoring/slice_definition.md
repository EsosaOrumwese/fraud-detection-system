## 1. Requirement Being Targeted

The requirement being targeted here is the Guy's and St Thomas' `Senior Data Analyst` expectation around:
- identifying workforce-data quality issues
- identifying reasons for workforce-data quality issues
- proposing solutions to overcome those issues
- ensuring workforce information is prepared and quality checked before release
- ensuring data-governance protocols are followed when releasing data to customers
- developing and delivering regular `KPI` and compliance monitoring reports
- using those reports to identify data-quality issues and governance breaches

This maps directly to the candidate-profile requirement that the analyst should be able to sound like someone who:
- treats data quality and information governance as part of the analytical job
- can detect issues, investigate causes, and turn them into corrective action
- can control the release of sensitive workforce information appropriately
- can build monitoring surfaces that expose governance risk rather than only summarise performance

This note exists because that requirement is easy to flatten into the vague statement:
`good with data quality and governance`

That is not the real burden.

The employer is asking for something sharper:
- workforce-data issue identification
- cause-aware quality investigation
- governance-safe release control
- regular `KPI` and compliance monitoring
- actionable detection of quality issues and governance breaches

## 2. The Analogue On The Current Platform

The current platform does not contain a literal Trust information-governance office, full workforce-security administration layer, or live `ESR` / `Oracle HRMS` access-control estate, so the slice has to use an honest analogue.

The closest truthful analogue is:
- one governed workforce-reporting lane already established in Guy's and St Thomas' `A + B`
- one explicit issue or discrepancy class over that lane
- one governance-safe release-control reading over sensitive workforce-style outputs
- one regular `KPI` / compliance-monitoring surface built from the same controlled base
- one corrective-reading note that explains what should change before broader release or reuse

So for this slice:
- `identify data quality issues and reasons` maps to `materialise one bounded issue class and one cause-reading over the workforce-reporting lane`
- `quality check information before release` maps to `make one release-safe control layer explicit before downstream use`
- `follow data-governance protocols when releasing data` maps to `show one governed release posture over the same sensitive reporting family`
- `develop regular KPI and compliance monitoring reports` maps to `build one compact monitoring surface from the same governed base`
- `use those reports to identify governance breaches` maps to `state one bounded compliance-risk interpretation from the monitoring layer`

The claim must therefore remain:
- workforce-data quality shaped
- governance and release-control shaped
- compliance-monitoring shaped
- platform-truth bounded
- careful not to imply literal governance-office ownership, full compliance-function authority, or whole-Trust workforce-data stewardship where this slice only proves one bounded monitoring-and-control pack

Default first-pass posture:
- workforce-data quality issue detection first
- governance-safe release control second
- `KPI` / compliance-monitoring surface third
- corrective-reading note fourth
- issue-class and release-control proof should be fixed from the inherited workforce-reporting pack before any broader governance-monitoring rhetoric is allowed
- stronger governance-office language only if the bounded evidence genuinely supports it

## 3. Relationship To Guy's And St Thomas' `A + B`

This slice is not a fresh foundation slice.

The cleanest bounded slice for this Guy's and St Thomas' requirement is:

`one workforce-data quality and governance pack with one explicit issue class, one KPI/compliance-monitoring surface, and one release-safe corrective-reading note`

- define one bounded workforce-data issue or discrepancy class over that lane
- materialise one compact `KPI` / compliance-monitoring surface from the same controlled base

- `can the governed workforce-reporting lane be extended into one quality-and-compliance monitoring pack that identifies issues, supports safe release, and guides corrective action?`

That means the slice should produce:
- one workforce-data quality summary
- one issue or discrepancy findings output

This slice is the best analogue for the Guy's and St Thomas' requirement because it proves:

without pretending to own the whole Trust governance or compliance function.
