## 1. Requirement Being Targeted

The requirement being targeted here is the NHS Frimley Integrated Care Board `Associate Data Analyst - Connected Care` expectation around:
- producing dashboards, infographics, and visually led analytical products
- using `SQL` and visualisation tooling to move from prepared data into usable outputs
- translating analytical findings into accessible language, narrative structure, and user-friendly insight products
- designing products for non-technical audiences rather than analyst-only consumption
- making complex population-health or service information easier to understand and apply

This maps directly to the Frimley candidate-profile requirement that the analyst should be able to sound like someone who:
- can shape data with `SQL` or equivalent preparation logic
- can build clear visual analytical products
- can turn analytical outputs into accessible narratives and guidance rather than technical dumps
- can make visual products usable for everyday non-technical readers

This note exists because that requirement is easy to flatten into the vague statement:
`good at dashboards`

That is not the real burden.

The employer is asking for something sharper:
- data shaping plus visual product delivery
- visual outputs designed for usability and accessibility
- translation of analytics into guidance-like insight
- a clear bridge from technical preparation to audience understanding

## 2. The Analogue On The Current Platform

The current platform does not contain a literal Connected Care dashboard estate, live `Power BI` workspace, or a full population-health communication studio, so the slice has to use an honest analogue.

The closest truthful analogue is:
- one governed compact analytical base that can be shaped into a stable visual-product layer
- one dashboard-style summary output
- one infographic-style or concise visual-story output
- one accessible explanation note that translates the same governed logic into user-facing language

So for this slice:
- `dashboard, infographic, and multimedia product capability` maps to `one bounded visual analytics pack with more than one presentation surface built from the same governed logic`
- ``SQL` plus visualisation tooling` maps to `one explicit shaping layer that turns compact analytical outputs into a visual-product-ready base`
- `translation into accessible insight` maps to `one concise explanatory surface that tells non-technical readers what the output means and why it matters`

The claim must therefore remain:
- visual-product shaped
- data-preparation shaped
- audience-accessibility shaped
- careful not to imply a full Connected Care tool estate, a live self-service dashboard platform, or a broad adoption programme where this slice only proves one bounded data-to-visual-product chain

The cleanest bounded slice for this requirement is:

`one data-to-visual-product pack with one shaped analytical base, one dashboard-style summary, one infographic-style insight surface, and one accessible explanation note`

- materialise one dashboard-style summary output from that base
- materialise one concise infographic-style or visual-story output from the same logic
- write one accessible explanation note telling a non-technical reader what the outputs show and what they should notice

The slice should answer one narrow question:
- `can one governed analytical base be shaped into visual products that remain accurate, readable, and genuinely more accessible to non-technical users than a standard report alone?`

That means the slice should produce:
- one visual-product scope note
- one shaped-base summary
- one dashboard-style output
- one infographic-style insight output
- one accessible explanation note
- one caveat or rerun note

This slice is the best analogue for the Frimley requirement because it proves:
- visual analytical product delivery

- accessible insight translation

without pretending to own the whole Connected Care dashboard and communications estate.
